# 상상휴게소 — 제품 요구사항 문서

> 문서 상태: 공모전 MVP 기준안
> 갱신일: 2026-11-13
> 대상: Hyundai Pleos Connect 차량용 Android 앱 공모전
> 앱 이름: 상상휴게소
> 영문명: SangsangRestStop
> 패키지·namespace·applicationId: `com.sangsangreststop.app`

## 1. 제품 개요

상상휴게소는 차량 안에서 어린이와 가족이 화면을 계속 바라보지 않고, 듣고 말하며 짧게 즐길 수 있는 음성 중심 놀이 앱이다. 화면은 놀이 선택과 상태 확인을 돕고, 핵심 진행은 가능한 범위에서 음성으로 제공한다.

상상휴게소는 MallangTori에서 분리한 독립 프로젝트이며 원본 프로젝트를 수정하지 않는다.

### 제품 원칙

1. 음성 우선: 질문, 힌트, 정답 확인과 전환을 음성 중심으로 제공한다.
2. 화면 최소화: 화면 조작을 게임 진행의 필수 조건으로 만들지 않는다.
3. 안전 우선: 주행 중 사용 가능 여부와 UI 제한은 Pleos 공식 정책 검증 후 결정한다.
4. 짧고 즐거운 놀이: 경쟁·랭킹보다 가족 대화와 참여에 집중한다.
5. 개인정보 최소화: 음성 녹음, 위치, 이동 이력을 불필요하게 저장하지 않는다.
6. 따뜻한 피드백: 오답과 무응답을 실패로 압박하지 않고 다시 시도할 수 있게 한다.

## 2. 사용자와 환경

- 어린이 탑승객: 음성으로 단어와 정답을 말한다.
- 보호자·가족: 게임 선택을 돕고 함께 참여할 수 있다.
- 기본 검증 환경: 안전한 정차 상태의 일반 Android 및 Pleos 테스트 환경.
- 주행 중 제공 범위: 공식 정책과 차량 상태 API 확인 전 미확정.
- 네트워크 불안정, 음성 인식 실패, 전화·내비 안내와 오디오 포커스 개입을 고려한다.

## 3. 공모전 MVP와 구현 상태

상태 의미:

- **구현**: 현재 저장소에 코드·리소스가 존재하고 기본 빌드·테스트 범위가 확인됨
- **부분 구현**: 일부 코드 또는 UI가 있으나 전체 사용자 흐름이나 실제 환경 검증이 남음
- **미구현**: 대시보드의 준비중 표시 외 게임 기능이 없음

| 게임 | 설명 | 현재 상태 |
| --- | --- | --- |
| 단어 짝짝꿍 | 마지막 글자로 새 단어를 이어 말한다 | 구현: 기존 WordChain 엔진·설정·진행 화면·설정 저장·단위 테스트 |
| 짜잔! 누구? | 앱의 단계별 힌트를 듣고 정답을 맞힌다 | 미구현: 준비중 카드만 제공 |
| 쫑긋 퀴즈 | 동물·탈것·악기 소리를 듣고 맞힌다 | 미구현: 준비중 카드만 제공 |

- 대시보드와 3개 게임 카드
- 게임 선택 → 규칙 설명 → 연습 → 본게임 → 종료 흐름
- 규칙 설명과 연습 각각 건너뛰기
- 규칙 다시 듣기와 다시 연습하기
- 게임별 온보딩 완료 저장
- 음성 인식과 음성 출력
- 일시정지·재개·종료
- 음성 인식 실패와 서비스 오류의 안전한 복구
- 실제 발생한 오류 하나만 표시하는 공통 팝업
- 화면을 보지 않아도 이해 가능한 음성 힌트

대시보드와 카드 3종은 구현됐다. 공통 온보딩, 게임별 완료 저장, 공통 팝업의 전체 런타임 연결은 미구현 또는 부분 구현이다.

### MVP 제외

- 기존 상상뚝딱
- 기존 스무고개
- 네 번째 이후 신규 게임
- 결제·구독·캐릭터팩 스토어
- 랭킹·경쟁·미션·보상
- 과거 이동·활동 이력
- 사용자 음성 녹음본의 영구 저장·공유
- 카메라·GPS로 외부 사물을 자동 인식하는 기능
- 검증되지 않은 웨이크워드·차량 이벤트 기능

기존 상상뚝딱과 스무고개 시안은 `docs/design/references`의 Legacy 참고 자료로만 보존한다. 실행 경로의 미사용 `mt_` 리소스는 별도 검증 후 삭제됐다.

## 4. 게임별 음성 온보딩

이 정책은 단어 짝짝꿍, 짜잔! 누구?, 쫑긋 퀴즈에 공통 적용한다. 현재 공통 온보딩 UI·상태·저장 기능은 미구현이다.

### 4.1 최초 실행 흐름

게임별 `onboardingCompleted`가 완료되지 않은 상태에서 게임을 선택하면 다음 순서로 진행한다.

#### STEP 1. 규칙 설명 선택

상상놀이친구가 “놀이 방법을 알려줄까?”라고 묻는다.

- “응”, “네”, “좋아” → 규칙 설명 진행
- “아니”, “싫어”, “괜찮아” → 규칙 설명 생략
- 설명이 끝나거나 명시적으로 생략되면 연습 선택 단계로 이동

#### STEP 2. 연습 선택

상상놀이친구가 “그럼 연습을 한 번 해볼까?”라고 묻는다.

- “응”, “네”, “좋아” → 해당 게임의 연습 1회 진행
- “아니”, “싫어”, “괜찮아” → 연습 생략
- 연습이 끝나거나 명시적으로 생략되면 본게임 진입을 확정

규칙 설명과 연습 선택은 서로 독립적이다. 규칙 설명을 생략해도 연습을 선택할 수 있고, 규칙을 들었다고 연습을 강제하지 않는다.

#### STEP 3. 본게임 시작

본게임 진입이 확정되면 선택한 게임의 기존 진행 구조를 시작한다. 단어 짝짝꿍은 기존 WordChain 설정·진행 구조를 보존하고, 공통 온보딩을 어댑터 또는 상위 흐름으로 연결한다.

### 4.2 이후 실행 흐름

게임별 온보딩 완료 사용자는 기본적으로 본게임으로 바로 진입한다. 다음 기능은 언제든 제공해야 한다.

- 규칙 다시 듣기
- 다시 연습하기

다시 듣기와 다시 연습을 실행해도 기존 `onboardingCompleted` 기록은 초기화하지 않는다.

### 4.3 음성 및 터치 선택

음성 명령을 기본 입력으로 사용한다.

- 기본 긍정 응답: “응”, “네”, “좋아”
- 기본 부정 응답: “아니”, “싫어”, “괜찮아”
- 공백, 어미와 유사 표현의 허용 범위는 구현 시 아동 발화 테스트로 검증한다.
- 긍정과 부정 판정이 불확실하면 임의로 선택하지 않는다.
- 화면에는 큰 ‘응’·‘아니’ 버튼을 함께 제공한다.

### 4.4 인식 실패와 무응답

- 최초 인식 실패 시 “응 또는 아니라고 말해줘!”라고 다시 안내한다.
- 재시도에서도 인식되지 않으면 화면의 ‘응’·‘아니’ 버튼을 안내한다.
- 인식 실패나 무응답을 자동으로 ‘아니’로 처리하지 않는다.
- 자동으로 본게임을 시작하거나 현재 단계를 생략하지 않는다.
- 입력이 불가능하면 현재 단계에서 안전하게 대기하거나 게임 선택 화면으로 돌아갈 수 있어야 한다.

### 4.5 TTS/STT와 입력 중복 처리

- 안내 TTS가 종료된 뒤 STT를 시작한다.
- TTS 출력 중에는 STT를 중지하여 앱 자신의 안내를 사용자 응답으로 인식하지 않게 한다.
- 하나의 선택 단계에서 확정된 응답은 한 번만 처리한다.
- 음성 입력과 터치 입력이 동시에 도착해도 최초 유효 선택 하나만 반영한다.
- 전화·내비 안내 등으로 중단되면 현재 세션의 온보딩 단계를 보존하는 방향으로 설계한다.
- Pleos 차량 이벤트에 따른 자동 중단·재개는 공식 지원과 실제 환경을 확인하기 전 완료로 표시하지 않는다.

### 4.6 완료 저장

- `onboardingCompleted`는 게임별로 관리한다.
- 규칙 설명이나 연습을 사용자가 명시적으로 생략한 경우에도 해당 단계는 정상 완료로 본다.
- 규칙 설명·연습을 완료하거나 명시적으로 생략하여 본게임 진입이 확정된 시점에 완료를 저장한다.
- 앱 강제 종료, 오류 또는 입력 불가로 온보딩이 중단되면 완료로 저장하지 않는다.
- 현재 세션의 단계·선택·재시도 상태와 영구 저장하는 완료 여부를 구분한다.

### 4.7 UX 목표

- 설명은 짧고 쉬운 문장으로 제공한다.
- 연습은 기본 1회로 구성한다.
- 정상 응답 흐름에서 게임 선택 후 약 30초 안팎에 본게임을 시작하는 것을 초기 UX 목표로 한다.
- 30초는 성능 보장 조건이 아니며 실제 아동 테스트 결과에 따라 조정한다.
- 실패 압박이나 부정적인 피드백을 사용하지 않는다.

## 5. 게임 요구사항

### 5.1 단어 짝짝꿍

기존 WordChain 엔진과 화면을 재사용한다.

- 앱과 사용자가 번갈아 단어를 말한다.
- 직전 단어의 마지막 글자와 다음 단어의 첫 글자를 검사한다.
- 두음법칙, 중복 단어, 허용 사전과 난이도는 기존 엔진 설정을 유지한다.
- 어려워하면 단계별 음성 힌트와 예시 단어를 제공한다.
- 음성 입력을 사용할 수 없으면 직접 입력 경로를 제공한다.
- 연습 결과는 본게임 상태에 포함하지 않는다.
- 기존 WordChain 클래스명은 내부 구현명으로 유지할 수 있다.

현재 상태:

- 엔진, 설정 저장, 설정 화면, 진행 화면, 단위 테스트 구현
- Pleos STT/TTS 어댑터 연결
- Android TTS 대체 구현과 직접 입력 대체 경로
- 사용자 일시정지와 백그라운드 일시정지 상태 구현
- 최초 규칙 설명·연습과 공통 종료 팝업의 런타임 연결은 미구현

### 5.2 짜잔! 누구?

앱이 정답을 하나 선택하고 힌트를 쉬운 순서부터 단계적으로 제공한다. 사용자는 힌트를 듣고 정답을 말한다.

- 기존 스무고개와 별개의 게임이다.
- 사용자가 예·아니요 질문을 하는 방식이 아니다.
- 정답과 힌트는 연령에 맞는 단어로 구성한다.
- 오답이면 다음 힌트를 제공하거나 다시 시도하게 한다.
- 힌트 수, 정답 범위, 난이도와 종료 조건은 구현 전에 확정한다.
- 정답·힌트 데이터는 우선 로컬 제공을 검토한다.
- 외부 LLM을 전제로 하지 않는다.
- 순수 Kotlin 상태 엔진과 단위 테스트를 우선 구현한다.

현재 상태: 엔진, 데이터, 설정·진행 화면 모두 미구현이며 대시보드에 준비중 카드만 제공한다.

### 5.3 쫑긋 퀴즈

동물·탈것·악기 소리를 재생하고 사용자가 정답을 말한다.

- 카테고리는 동물, 탈것, 악기다.
- 음원 재생 중 STT가 음원을 사용자 발화로 오인하지 않도록 입력을 중지한다.
- 재생 완료 후 답변을 듣는다.
- 다시 듣기와 음성 힌트를 제공한다.
- 정답·오답·무응답 모두 부담 없는 피드백을 제공한다.
- 음원은 사용 권한·출처·라이선스를 기록한다.
- 음원 파일을 추가하기 전 APK 크기와 오디오 포커스를 검토한다.

현재 상태: 엔진, 화면, 문제 데이터, 음원 모두 미구현이며 대시보드에 준비중 카드만 제공한다.

## 6. 공통 음성·오디오

- `SpeechInput`과 `SpeechOutput` 인터페이스를 공통 경계로 유지한다.
- `PleosSpeechInput`, `PleosSpeechOutput`, `AndroidTtsSpeechOutput`을 재사용한다.
- TTS, 효과음, STT가 동시에 활성화되지 않도록 상태를 조정한다.
- 권한 거부, 무응답, 인식 실패에 타임아웃과 안전한 종료 경로를 제공한다.
- 실제 음성 녹음 파일을 영구 저장하지 않는다.
- 사용자 노출 목소리 이름은 `상상놀이친구`다.

확인된 사실:

- Pleos STT/TTS SDK 의존성, 권한, 어댑터 코드가 존재한다.
- 단어 짝짝꿍은 TTS 후 STT를 요청하고, STT 불가 시 직접 입력으로 대체한다.
- 대시보드에 `상상놀이친구`가 표시된다.
- Pleos 에뮬레이터에서 말하기 → 듣기 상태 전환을 확인한 작업 기록이 있다.

검증 필요:

- Pleos STT 실제 인식 정확도와 무응답 원인
- TTS 실제 출력 품질
- 목소리 선택·저장 기능과 실제 지원 음색
- 주행 중 마이크·음성 게임 허용 범위
- 웨이크워드와 백그라운드 동작
- 쫑긋 퀴즈 음원 재생과 Pleos 오디오 포커스

## 7. 시스템 이벤트와 공통 팝업

- 전화·내비 안내가 감지되면 게임과 음성 출력을 일시정지한다.
- 개입 종료 후 자동 재개 가능 여부는 공식 API와 정책 확인 후 결정한다.
- 시동 OFF 시 현재 게임 세션을 초기화하되 영구 설정은 유지하는 방향을 검토한다.
- 같은 질문·힌트·문제의 중복 진행을 방지한다.
