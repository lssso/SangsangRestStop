# 상상휴게소 — UI 디자인 가이드

> 적용 대상: 공모전 MVP
> 상태: 대시보드 1차 확정 시안과 현재 `sr_` 리소스 적용 기준

## 1. 기준과 우선순위

1. Hyundai Pleos 공식 디자인·안전 정책
2. `docs/PRD.md`의 확정 요구사항
3. `docs/design/references/1-0. 상상휴게소 떠나는 즐거운 놀이 여행(3개).png`
4. 접근성·아동 친화 원칙
5. 현재 Compose 구현
6. 그 밖의 Legacy 참고 시안

과거 게임·목소리·팝업 시안은 시각적 참고 자료일 뿐 현재 MVP의 구현 완료 기준이 아니다.

## 2. 제품 인상

- 차 안에서 잠시 쉬어 가는 따뜻하고 편안한 공간
- 어린이가 쉽게 알아볼 수 있는 큰 카드와 짧은 문구
- 밝은 자연·하늘 계열 배경과 친근한 캐릭터
- 음성 상태를 화면에서도 이해할 수 있는 명확한 피드백
- 정답·오답보다 참여와 다시 시도를 격려하는 분위기

## 3. 대시보드

표시 순서:

1. 단어 짝짝꿍
2. 짜잔! 누구?
3. 쫑긋 퀴즈

단어 짝짝꿍은 현재 진입 가능하다. 두 신규 게임은 구현 전까지 준비중으로 표시한다.

현재 적용 요소:

- `sr_bg_dashboard_139.png`: 캐릭터가 포함된 배경
- `sr_logo_main.png`, `sr_logo_symbol.png`
- `sr_card_word_bg.png` + `sr_card_word_art.png`
- `sr_card_who_bg.png` + `sr_card_who_art.png`
- `sr_card_sound_bg.png` + `sr_card_sound_art.png`
- 하단 현재 목소리 `상상놀이친구` 영역
- 안전 영역과 화면 폭에 따른 카드 행·가로 스크롤 대응

카드 배경과 아트워크는 Compose에서 독립 레이어로 유지한다. PNG 내부 그림과 Compose 요소를 중복 배치하지 않는다.

## 4. 게임 카드

### 단어 짝짝꿍

- 화면 표시 이름은 단어 짝짝꿍으로 통일한다.
- 기존 WordChain 설정·진행 UI와 캐릭터 시각 언어를 재사용한다.
- 대시보드 카드 이미지는 현재 `sr_card_word_*`를 사용한다.

### 짜잔! 누구?

- 단계별 힌트가 하나씩 공개되는 느낌을 표현한다.
- 사용자가 예·아니요 질문을 이어 가는 게임으로 보이게 만들지 않는다.
- 질문 횟수 20개 또는 예·아니요 질문 UI를 사용하지 않는다.
- 대시보드 카드는 `sr_card_who_*`가 적용됐지만 설정·진행 화면과 전용 삽화는 미구현이다.

### 쫑긋 퀴즈

- 귀, 음파 또는 동물·탈것·악기의 소리 인지를 표현한다.
- 특정 정답을 지나치게 노출하는 이미지는 피한다.
- 재생 중, 듣는 중, 정답 처리 중 상태를 구분한다.
- 대시보드 카드는 `sr_card_sound_*`가 적용됐지만 설정·진행 화면, 상태 아이콘과 음원은 미구현이다.

## 5. 단어 짝짝꿍 화면

기존 `WordChainSetupScreen`과 `WordChainPlayScreen`을 재사용한다.

유지:

- 난이도·힌트 설정
- 이전 단어와 차례 표시
- 마이크·직접 입력·다시 듣기·힌트 동작
- 기존 캐릭터와 배경
- 밝은 파스텔 카드와 큰 텍스트

남은 작업:

- 공통 규칙 설명·연습·종료 흐름 연결
- 공통 팝업의 런타임 연결
- 실제 Pleos 음성 품질·인식 검증

내부 WordChain 클래스명은 유지한다. 활성 화면 이미지는 `sr_bg_wordchain_*`, `sr_char_wordchain_*`, `sr_deco_wordchain_*`, `sr_icon_wordchain_*`를 사용한다.

## 6. 신규 게임 화면 원칙

공통 화면 구조:

- 게임 제목과 짧은 설명
- 현재 음성·오디오 상태
- 큰 중심 캐릭터 또는 대표 삽화
- 정답을 직접 노출하지 않는 상태 정보
- 다시 듣기, 힌트, 일시정지, 종료
- 텍스트 입력은 음성 사용 불가 환경의 대체 경로로만 검토

짜잔! 누구?:

- 힌트 단계가 증가하는 것을 어린이가 이해할 수 있게 표현
- 오답을 실패나 감점으로 강조하지 않음
- 다음 힌트를 자연스럽게 안내

쫑긋 퀴즈:

- 소리 재생 중에는 마이크 듣기 상태와 혼동되지 않게 표시
- 다시 듣기를 큰 행동으로 제공
- 음원 출처와 라이선스는 프로젝트 기록에서 관리

두 신규 게임의 화면은 아직 계획이며 구현된 UI로 간주하지 않는다.

## 7. 목소리 표시와 선택

- 사용자 노출 목소리 이름은 `상상놀이친구`다.
- 현재 대시보드는 이름과 “목소리 변경” 동작을 표시하지만 실제 선택·저장 화면은 구현되지 않았다.
- `docs/design/references/2.놀이친구 캐릭터 목소리 선택 화면.png`은 참고 시안이다.
- 실제 지원 음색과 Pleos SDK 제약을 검증하기 전 선택 기능을 완료로 표시하지 않는다.

## 8. 공통 음성 온보딩

현재 공통 온보딩 화면과 상태 저장은 미구현이며, 아래는 향후 UI 원칙이다.

최초 실행 흐름:

1. 규칙 설명 선택
2. 규칙 설명 완료 또는 생략
3. 연습 선택
4. 연습 1회 완료 또는 생략
5. 본게임

규칙 설명과 연습 선택은 서로 독립적으로 표현한다.

### 선택 화면

- 상상놀이친구의 현재 질문을 짧고 큰 문장으로 표시한다.
- 규칙 선택 질문은 “놀이 방법을 알려줄까?”로 표시한다.
- 연습 선택 질문은 “그럼 연습을 한 번 해볼까?”로 표시한다.
- 음성을 기본 입력으로 사용하면서 큰 ‘응’·‘아니’ 버튼을 함께 제공한다.
- 듣는 중, 말하는 중, 인식 처리 중과 입력 대기 상태를 색상 외 텍스트·아이콘으로 구분한다.
- 화면을 보지 않아도 선택 방법과 현재 단계를 이해할 수 있도록 음성으로 안내한다.

### 실패와 대체 입력

- 첫 인식 실패에는 “응 또는 아니라고 말해줘!”라고 부담 없이 다시 안내한다.
- 두 번째 실패에는 큰 화면 버튼을 안내한다.
- 무응답이나 불확실한 응답을 ‘아니’로 표시하거나 다음 단계로 자동 전환하지 않는다.
- 입력이 불가능하면 안전한 대기와 게임 선택 화면 복귀 행동을 제공한다.
- 음성·터치가 동시에 들어와도 화면은 최초 유효 선택 한 번만 반영한다.

### 이후 실행과 접근성

- 완료 사용자는 기본적으로 본게임으로 진입하되 규칙 다시 듣기와 다시 연습하기를 찾기 쉬운 위치에 제공한다.
- 다시 듣기·연습 실행이 완료 기록 초기화로 보이지 않게 한다.
- 문장은 짧고 아동 친화적으로 작성하며 실패 압박이나 부정적 표현을 사용하지 않는다.
- 연습은 기본 1회이고, 약 30초 안팎의 본게임 진입은 초기 UX 목표이지 보장 조건이 아니다.
- 전화·내비 중단 상태 UI는 Pleos 공식 지원과 실제 환경을 확인한 뒤 확정한다.

## 9. 공통 팝업

기존 `CommonPopup` 구현과 `sr_common_*` 이미지를 유지한다.

- 배경 딤
- 흰색 구름형 패널
- 큰 제목과 짧은 본문
- 상황별 아이콘·캐릭터
- 1~3개의 큰 행동 버튼

지원 UI:

- 음성 인식 실패
- 네트워크·서비스 오류
- 전화
- 내비게이션
- 사용자 일시정지
- 게임 종료

Compose Preview와 Debug 팝업 갤러리는 존재하지만 실제 게임·차량 이벤트 흐름의 모든 동작이 연결된 것은 아니다. 전화·내비 종료 후 자동 재개, 통화 실행과 차량 UI 제어는 Pleos API·안전 정책 검증 전 확정하지 않는다.

## 10. 색상·타이포그래피

- 밝은 테마를 기본으로 한다.
- 짙은 남색 텍스트와 밝은 하늘·자연 배경을 유지한다.
- 게임별 포인트색은 카드 구분을 돕되 색상만으로 상태를 전달하지 않는다.
- 어린이가 읽기 쉬운 짧은 한국어와 충분한 크기·대비를 사용한다.
- 현재 PNG에서 추출한 색을 최종 Pleos 브랜드 색으로 임의 확정하지 않는다.
- 최종 글꼴은 라이선스와 Pleos 가이드를 확인한다.

## 11. 이미지·캐릭터·아이콘

현재 적용:

- 상상휴게소 런처 아이콘 `sr_app_icon.png`과 adaptive icon XML
- 상상휴게소 로고와 심볼
- 캐릭터 포함 대시보드 배경
- MVP 게임 카드 3종의 배경·아트워크
- 단어 짝짝꿍 설정·진행 리소스
- 공통 팝업 리소스

추가 제작 필요:

- 짜잔! 누구? 설정·진행 삽화
- 쫑긋 퀴즈 설정·진행 삽화와 음원 재생 상태 아이콘
- 필요 시 게임별 온보딩 삽화
- 배포 전 Play Store용 아이콘 규격 최종 검토

기존 여자아이·남자아이·토끼·구름 캐릭터 외형과 현재 UI를 임의로 변경하지 않는다. 임의 생성 이미지나 합성 시안의 무단 잘라쓰기를 최종 자산으로 사용하지 않는다.

## 12. 리소스 용도

- `app/src/main/res/drawable-nodpi`: 앱에서 직접 사용하는 `sr_` PNG
- `app/src/main/res/drawable*`: 런처 아이콘 XML
- `assets/backgrounds`: 대시보드 배경 원본·편집·재수출용 파일
- `assets/dashboard`: 현재 대시보드 카드 원본·편집·재수출용 파일
- `docs/design/references`: 최신 확정 시안과 Legacy 참고 시안
- `docs/design/references/backup`: Git 제외 백업

실행 경로와 루트 `assets`에 있던 미사용 레거시 파일 79개는 백업·SHA-256·build·test 검증 후 삭제됐다. 현재 리소스 정책은 삭제된 파일의 보존을 전제로 하지 않는다.

## 13. Legacy 참고 자료

현재 Legacy 보존 대상은 주로 `docs/design/references`의 시안이다.

- 과거 목소리 선택 시안
- 기존 끝말잇기 설정·진행 시안
- 기존 “나는 누구일까요” 설정·진행 시안
- 공통 종료·오류·휴식·내비·전화 팝업 시안

이 자료는 실행 리소스가 아니다. 기존 끝말잇기 시안은 단어 짝짝꿍 구조 참고로, 공통 팝업 시안은 브랜드·문구를 현재 기준으로 해석한 구조 참고로 사용할 수 있다.

빈 Legacy 자리표시자 디렉터리는 현재 구조에서 제거한다. 삭제된 실행 리소스를 현재 보존 자산으로 기재하지 않는다.

## 14. Pleos 검증 필요

- 앱이 사용할 수 있는 실제 렌더링 영역
- 시스템 상태바·차량 UI 소유 범위
- 주행 중 표시·터치·음성 입력 허용 범위
- 버튼 최소 크기, 안전 영역과 포커스 규칙
- 전화·내비 이벤트와 팝업 중복 여부
- STT 실제 인식 정확도와 TTS 출력 품질
- TTS·효과음·STT 오디오 포커스
- 에뮬레이터와 실제 차량 화면 차이

확인 전에는 기존 시안의 플랫폼 UI를 앱 안에 복제하지 않는다.

## 15. 접근성

- 색상 외 텍스트·아이콘으로 상태 표시
- 큰 터치 영역과 명확한 포커스
- 듣는 중, 재생 중, 처리 중, 말하는 중 상태 구분

- 여러 명이 동시에 말하면 한 명씩 말하도록 안내
